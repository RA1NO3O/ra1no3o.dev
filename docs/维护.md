# 维护手册

个人站。Astro 在本机构建成静态 HTML，再上传到 Cloudflare Pages。GitHub 仓库不会自动构建，也不会自动发布。

线上地址是 https://ra1no3o.dev 。`/` 会立刻跳到 `/en`。四种语言各自一套页面：

| 语言 | 地址前缀 | 页面 `lang` |
| --- | --- | --- |
| English | `/en` | `en` |
| 简体 | `/zh-cn` | `zh-Hans` |
| 繁體 | `/zh-tw` | `zh-Hant` |
| 日本語 | `/ja` | `ja` |

每种语言都有首页、设备、游戏三个页面，例如 `/zh-cn/gear`、`/ja/play`。

## 环境

- Node.js `>= 22.23.4`。版本写在 `package.json` 的 `engines` 里。
- 依赖只有 Astro。安装：`npm install`。
- 预览：`npm run dev`，然后打开 http://localhost:4321/zh-cn 。
- 开发服务如果要丢到后台：`npx astro dev --background`。查看、看日志、停掉分别是 `npx astro dev status`、`npx astro dev logs`、`npx astro dev stop`。
- 本机的开发服务只监听 IPv6 的 `localhost`。用 `http://127.0.0.1:4321` 会连不上，用 `http://localhost:4321`。

改完内容先在本地看四种语言，再按文末的步骤构建和部署。

## 改哪一份文件

| 想改的东西 | 文件 |
| --- | --- |
| 首页那句话、简介、页脚位置、导航名、设备分组名、备注译文、游戏名 | `src/i18n/copy.ts` |
| 语言列表本身 | `src/i18n/locale.ts`，还要改 `astro.config.mjs` |
| 首页链接、设备清单、游戏 ID、站点名 | `src/data/site.ts` |
| 链接前面的小图标 | `public/icons/` 和 `src/data/icons.ts` |
| 首页那张照片 | `src/assets/photos/` 和 `src/pages/[locale]/index.astro` |
| 页面排版 | `src/pages/[locale]/` 里对应的 `.astro` |
| 共用头部、导航、语言切换 | `src/layouts/Base.astro`、`src/components/Nav.astro` |
| 颜色、字体、间距 | `src/styles/global.css` |
| 搜索引擎地图 | `public/sitemap.xml`（手写的，构建不会自动更新） |

`dist/` 是构建结果。不要手改。下次 `npm run build` 会整目录覆盖。

`copy.ts` 末尾有 `satisfies Record<Locale, Copy>`。四种语言的字段必须一致，少一个字段，`npm run build` 会报错。这是故意的。

## 四种语言要一起改

一句给人看的话，在 `src/i18n/copy.ts` 的 `en`、`zh-cn`、`zh-tw`、`ja` 四段里各写一遍。

产品名、型号、账号这些不翻译，放在 `src/data/site.ts`。会随语言变的句子才进 `copy.ts`。

设备备注有两种写法：

- 写成 `"mac.spec"` 这种键。键要先加进 `copy.ts` 顶部的 `NoteKey`，再在四种语言的 `notes` 里各写一句。页面显示译文。
- 写成普通字符串，例如 `"256GB"`。页面原样显示，不翻译。

配件名字也一样。`desk.sn580` 这种名字会去 `notes` 里找译文；找不到就原文显示。

## 首页

文案在 `copy.ts`：

- `sentence`：标题下面那句大字。
- `summary`：紧接着的自我介绍。
- `location`：页眉里的地点，现在是杭州。
- `homeDescription`：给搜索引擎和社交预览用的简介，页面上不显示。
- `photos`：照片小标题。
- `photoAlt`：照片的替代文字。要描述画面里有什么，四种语言各写一句。

个人链接在 `src/data/site.ts` 的 `profiles`。追加一项就会出现在首页底部：

```ts
{ label: "Bluesky", href: "https://bsky.app/profile/ra1no3o.dev", rel: "me" },
```

`label` 用网站自己的英文名，和 GitHub、Steam 一样，不进翻译文件。`rel: "me"` 只加在确实是你本人的主页上。

链接要显示图标时，看下面的「图标」一节。没有图标也能点，只是文字。

照片目前只有一张，直接写在 `src/pages/[locale]/index.astro`，不是一份清单。换照片时：

1. 把新图放进 `src/assets/photos/`。用 JPEG 或 PNG，长边 2400 像素左右就够。页面栏宽大约 640 像素，Astro 会再生成更小的图。不要提交手机原图，一张能有 10MB。
2. 改这行 import，指向新文件。
3. 改 `taken`。只写拍摄当天的 `YYYY-MM-DD`。页面用 UTC 的这一天来排日期，避免时区把日期提前或推后一天。
4. 改 `copy.ts` 里四种语言的 `photoAlt`。

再加一张，就在同一个 `<section>` 里再复制一个 `<figure class="photo">`，另做一次 import。日期写在各自的 `<time datetime="...">` 上。

## 设备页

清单在 `src/data/site.ts` 的 `gear`。每一组的 `id` 必须是 `copy.ts` 里的 `GroupId`：`phone`、`tablet`、`mac`、`desktop`、`audio`、`consoles`、`wearable`。分组标题是 `copy.ts` 的 `groups`。

一条设备：

```ts
{
  name: "11-inch iPad Pro",
  href: apple("ipad-pro"),
  notes: ["tablet.spec"],
  parts: [
    { name: "Magic Keyboard and Magic Trackpad" },
    {
      name: "Lecoo M2721PL",
      href: "https://item.m.jd.com/product/10062746266185.html",
      note: "display.lecoo",
    },
  ],
}
```

- `name` 是型号，不翻译。
- `href` 可以是一条 URL，也可以是四种语言各一条。Apple、ASUS、ROG、Razer、AMD 已经有 `apple()`、`asus()`、`rog()`、`razer()`、`amd()`，传入官网路径即可。
- `notes` 是型号下面的小字。
- `parts` 是配件，还可以再嵌 `parts`。

新开一个分组时，要同时改 `GroupId` 和四种语言的 `groups`。

## 游戏页

公开 ID 在 `src/data/site.ts` 的 `games`。显示名在 `copy.ts` 的 `games`。两边的 `id` 必须对上，类型是 `GameId`。

```ts
// site.ts
{ id: "zzz", href: "https://zzz.mihoyo.com", code: "16244285" }

// copy.ts，四种语言都要有这个 id
zzz: { name: "绝区零" }
```

`note` 可选，显示在名字后面，例如「日服」。`href` 可选；没有链接就只显示名字和 ID。

PlayStation 账号单独放在 `playstation`，不进 `games` 数组。

## 图标

`src/components/IconLink.astro` 按链接的域名找图标。域名写在 `src/data/icons.ts`。文件放在 `public/icons/`，构建后地址是 `/icons/文件名`。

```ts
"bsky.app": "/icons/bsky.app.png",
"space.bilibili.com": "/icons/bilibili.com.png",
```

约定：

- 64×64 的 PNG。透明底。
- 用彩色标志，浅色和深色背景上都要看得清。
- 不要在 `global.css` 的 `.site-icon` 上加 `background`。以前加过一层白底，深色模式下每个图标都像贴了白块。
- 同一个图标可以给多个域名用，例如 `discord.com` 和 `discord.gg`。

## 加一个新页面

现有页面是 `src/pages/[locale]/index.astro`、`gear.astro`、`play.astro`。照 `play.astro` 复制一份，例如 `notes.astro`，然后：

1. `Base` 的 `path` 设成 `"notes"`。这个值要加进 `src/i18n/locale.ts` 的 `RoutePath`。
2. 在 `src/components/Nav.astro` 的 `pages` 数组里加一项。
3. 在 `copy.ts` 的 `nav` 里给四种语言各起一个导航名，再写这个页面的标题和简介。
4. 在 `public/sitemap.xml` 里给四种语言各加一条 `<url>`。地图是手写的。

`src/pages/index.astro` 只负责把 `/` 转到 `/en`，还有无 JavaScript 时的语言列表。加语言时要改这里。加普通页面不用改它。

## 样式

全部在 `src/styles/global.css`。没有 Tailwind。

- 栏宽是 `--measure: 40rem`。
- 颜色是 `--bg`、`--ink`、`--muted`、`--line`、`--accent`。深色由 `prefers-color-scheme: dark` 切换，不要写死一套背景。
- 英文字体用 `--sans` 和 `--serif`。简体、繁体、日文在 `:lang(...)` 里换了字体。
- 分组标题用 `.group h2`。英文会变成大写；中文和日文保持原样。

## 构建

```sh
npm run build
npm run preview
```

`preview` 用来看 `dist/` 里的成品，而不是开发服务器。确认首页照片、新链接、设备页都在，再部署。

构建失败时，先看是不是 `copy.ts` 少了某个语言的字段，或是 `GameId`、`GroupId`、`NoteKey` 和数据对不上。

## 部署

站点在 Cloudflare Pages，项目名是 `ra1no3o-dev`。绑定的域名是 `ra1no3o.dev` 和 `www.ra1no3o.dev`。这个项目没有连接 Git，所以上传的是本机的 `dist/`。

账号是 `ra1no3o@icloud.com`。没登录时先执行 `npx wrangler login`。

```sh
npm run build
npx wrangler pages deploy dist --project-name ra1no3o-dev --branch main
```

`--branch main` 会发到生产环境。不带这个参数时，先看命令印出来的 Environment 是不是 Production，再把链接发出去。

发完打开 https://ra1no3o.dev/zh-cn ，强制刷新。Pages 有缓存，旧页面会再留一会儿。

回滚：到 [Cloudflare Pages 的部署列表](https://dash.cloudflare.com/) 里打开项目 `ra1no3o-dev`，把上一个 Production 部署重新设为当前版本。不需要重新构建。

仓库另有一个旧项目 `ra1no3o`，域名是 `ra1no3o.pages.dev`。不要把新站部署到那个项目。
